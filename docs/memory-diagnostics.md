# 内存诊断

性能验证时可设置 `WEBPILOT_AUTOMATIC_HEAP_SNAPSHOTS=false`，只关闭自动堆快照，保留轮转内存日志、会话/队列体量和高水位诊断。默认仍自动采集；手动采集不受这个开关影响。同步堆快照会阻塞被采集进程，因此测量接口延迟时必须单独记录或排除采集时间。

重启后端后，原生进程监控自动将 JSONL 写入 `APP_DATA_DIR/diagnostics/memory/`；未指定 `APP_DATA_DIR` 时为项目的 `runtime/diagnostics/memory/`。

- 默认每 60 秒记录；堆使用率达到 75% 后，每 10 秒记录。`WEBPILOT_MEMORY_LOG_INTERVAL_MS` 调整常规采样间隔。
- 日志文件按角色和 PID 区分，每个约 10 MiB 轮转，本目录最多保留 20 个匹配的日志文件。轮转只删除该诊断目录内匹配命名的日志，不清理业务数据。
- 首次进入高压力、压力级别变化或高压力下堆比上次报告增长 128 MiB 时，打印终端提示并记录 `process.memory.high-water`。记录含堆空间、进程资源、会话分类体量、持久化队列体量。
- 默认在监控启动时自动采集 `startup` 基线；堆比启动时增长 512MiB 或堆上限的 10%（取较小值）时采集 `growth` 快照；达到 1GiB 或堆上限的 50%（取较小值）时采集 `high-water` 对比快照。75% 仍是内存压力告警线，不再等到该告警才写快照。每秒检查触发条件，每个进程每类成功采集一次。失败会记录原因，至少间隔一分钟后在对应条件下重试。
- `diagnostics.browserChat.largestSessions` 最多列出 20 个会话，分类包括消息、步骤、日志、输出周期、子 Agent、模型上下文、排队消息和待持久化数据。全局遍历限制为 50,000 个节点、12 层，达到边界会标记 `truncated`。共享对象只归入第一次遇到的分类；这是字符串和二进制载荷估算，不能当作 V8 的实际 retained size。
- `diagnostics.databaseWriteQueue` 包含待写入／正在写入的载荷字节数、语句数、最大写入和最老任务年龄。字符串按 UTF-16 估算，不包括对象开销；不记录 SQL、参数正文或凭证。

## 采集与分析

管理员在后端运行状态页面点击“采集堆快照”，也可通过已认证的 `POST /api/admin/ai-operations/runtime` 请求触发（带项目配置的 basePath）。只能采集处理该请求的后端进程，不包含独立浏览器、代码沙箱或生产环境的 UI 进程。

快照会暂停该 Node 进程，可能包含会话正文和密钥，仅写到本机，不提供公开下载。不再用系统空闲内存估算拦截采集；磁盘空间不足时仍会拒绝，每分钟最多一次，每种进程角色保留 3 份，UI 与 API 不互相删除基线。页面和日志显示文件路径、PID 和采集时间。

1. 服务重启后自动生成文件名含 `startup` 的启动基线。
2. 增长阈值和对比阈值分别生成同一 PID、文件名含 `growth` 和 `high-water` 的快照。启动基线包含较少已加载模块，比较时需要区分正常模块加载与持续增长；必要时手动补充任务空闲时的快照。本进程清理旧快照时保留自己的启动基线。
3. 在 Chrome DevTools 的 Memory 面板加载两份 `.heapsnapshot`，使用 Comparison 查看增量，按 Retained Size 排序，展开 Retainers 找到持有路径。
4. 将持有路径与同时间日志对照：会话分类／队列同步增长时查业务持有；这些分类已下降而堆仍高时查编译缓存、SDK、闭包或其他进程级对象。载荷估算不涵盖整个堆，不能单凭估算归零排除泄漏。

OOM 后保留 `.jsonl` 和已有快照即可回查；只有 GC 栈、没有目标进程的快照时，无法还原具体对象的持有关系。

自动采集受磁盘和一分钟间隔限制，失败原因见 `process.memory.heap-snapshot.auto-failed`。优先使用提前生成的 `growth` 快照与启动基线比较。快照会同步暂停进程并消耗额外内存；突发分配或事件循环长期阻塞可能使采样来不及触发，因此不保证每次 OOM 前都有高水位快照。
