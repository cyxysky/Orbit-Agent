# Orbit Agent 上下文管理

当前主对话、自动化和子 Agent 经过统一的 executeInteractiveBrowserTurn，由 OpenAI Agents SDK Runner 运行工具循环。Orbit 管理持久化历史、上下文预算、语义压缩、权限和界面事件。完整模块清单及迁移验收见 [Agents SDK 迁移与运行说明](./agents-sdk-migration.md)。

## 历史的唯一来源

模型活动历史存于 workspace_record 的 execution 集合、agents-sdk:<scope> 作用域，并校验 userId 和 revision。主任务和子任务使用各自 contextScope。业务消息、步骤、modelContext.records 和日志用于展示、检索及审计；后续请求从数据库 Agent 会话加载，不重新拼接两份业务转录。

本执行路径使用应用管理历史回放，不同时启用 SDK session 自动追加、conversationId 或 previousResponseId。首次创建作用域时可采用业务入口提供的已有对话消息；不读取旧 Codex rollout 或线程绑定。

## 每次模型请求

1. 从同一运行的 SDK 原始历史提取新后缀，加入最近一次已压缩的投影。
2. 使用当前用户和会话实际可调用的工具，生成管理员模板及按需资料。
3. 通过 prepareRuntimeContext 计算预算、投影资料并在需要时生成历史摘要。
4. 原始证据先归档，替换后的历史检查点提交后才发送模型请求。
5. 通过官方 AI SDK 模型适配器调用既有供应商，并保留实际输入量、缓存量和输出量。
6. 模型输出和工具结果分别提交；待人工审批时另存 SDK RunState。

供应商的 reasoning 签名和其他元数据保留在 SDK 原项目中。投影消息按内容引用复用没有改写的项目；多工具调用属于一个 assistant 交换，其后紧接完整的工具回执。工具图片及文件在发往供应商时投影为该批回执之后的用户媒体输入，防止兼容接口把图片当成 JSON 文本；该投影不累计进历史。

## 压缩设置

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| AI_CONTEXT_WINDOW_TOKENS | 256000 | 模型未配置最大上下文时使用的窗口。 |
| AI_CONTEXT_SAFETY_RESERVE_TOKENS | 4096 | 协议与生成安全预留；输入预算为窗口减去该值。 |
| AI_CONTEXT_COMPRESSION_TRIGGER_RATIO | 0.85 | 达到输入预算的相应比例后尝试压缩。 |
| AI_CONTEXT_COMPRESSION_TARGET_RATIO | 0.25 | 压缩目标；实际仍须保留必要指令和证据。 |
| AI_CONTEXT_KEEP_RECENT_BLOCKS | 4 | 预算内优先保留的最近工具交换数量。 |
| AI_IMAGE_CONTEXT_ESTIMATE_TOKENS | 1200 | 每张图片的启发式预算。 |

AI_RUNTIME_MAX_TURNS 默认 100，限制一次任务的模型调用轮数；审批恢复仍属于同一次任务。

压缩复用现有摘要校验、源引用、加载规范保护、最近交换保护及 contextRead。摘要生成有独立取消和超时，不进行答案二次审核。未通过校验的摘要不会替换原文；超过硬输入预算时明确失败。压缩完成事件在检查点保存后发布，不能仅凭摘要请求返回就显示压缩完成。

当前运行资料与时间属于每次请求可替换的引用资料，放在稳定历史之后，不作为新的用户任务累计保存。管理员提示词只有显式引用时间变量时才在主模板中展开时间。运行时日期参考仍按既有设置提供。

## 工具、中断与恢复

工具真实调用 ID 在执行前登记，结果与其对应。SDK 审批暂停快照可以在同一次运行恢复。开始执行前使旧审批快照失效，并持久记录开始状态；恢复时不会从旧审批快照重复执行已经开始的动作。

工具结果未保存时使用执行日志区分“未执行”和“结果未知”；已保存结果回到原交换中。结果未知不能作为业务成功，也不能作为自动重放的许可。SDK 自行拒绝的无效 JSON 等结果也会进入 Orbit 工具日志。

取消信号传给 Runner、模型及 CAP 工具。文件、浏览器或网络操作是否已被外部系统完成，必须根据已保存回执或重新读取的当前状态判断。

## 用量、流式和 UI

实际请求前计算系统、工具、消息和图片预算，供应商返回输入用量后校准总量。实时速度可使用明确标记的估算值；终态速度、Token 和缓存指标使用供应商统计。Agents 直接调用模型，不经过 streamText，因此应用显式补录原有本地监控指标。

文本、思考和工具参数使用临时流式状态，不逐 token 写日志。工具启动、进度和结束使用同一个调用 ID。供应商重复使用的局部文本 ID 带上模型请求 ID，避免覆盖前一轮输出。回复草稿保持在对应生成回复工具下面。

上下文检查点等待对应数据库事务提交。现有聊天推送、按会话合并通知、历史分页及阅读位置逻辑继续使用业务层实现。公开日志隐藏执行引擎和内部运行字段；内部诊断保留原错误证据。SDK tracing 关闭，使用应用已有本地监控与日志。

## 运行依赖与验证

主执行链不再启动 Codex App Server 或本地 Responses 协议桥。模型层仅支持 OpenAI 与 Anthropic 兼容协议，语言和媒体生成均已移除 Codex CLI 驱动。

本轮不运行 dev/build，不新增测试源码，不提交或推送。真实模型、真实浏览器任务和完整页面链路的验证范围，以迁移文档中实际记录为准。
