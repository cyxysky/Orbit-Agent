# 对话上下文管理

上下文管理负责构造预算内、来源明确、能够从中止和重试中恢复的模型请求。它不维护另一份任务待办，也不根据历史目标自行安排下一步。

## 数据与职责

- `records`：不可变的内容寻址原文。用户消息、模型消息、工具调用和结果独立存储，可按引用回读。
- `history`：按发生顺序排列的对话记录引用。相同内容可以出现多次，两次相同提问是两次消息。
- `active`：当前保留的原始对话片段。不保存请求背景、运行清单或循环生成的待办。
- `continuationSummary`：唯一的历史摘要，格式为 `{version: 1, text: string}`，没有 `goal`、`nextStep` 或“继续执行”命令。
- `backgroundRef`：最近请求背景的引用，用于恢复与请求一致的 token 估算。
- `lastRequest`：精简的内部预算快照，包含数量、预算、模型以及系统提示、工具定义的引用，没有逐条保留/归档清单，不显示在 AI 输入日志中。

子任务保留独立的 history、active、摘要和检索状态，共用持久化基础设施。检查点只传递新增记录，避免每次传递整个原文集合。

## 请求构造

1. 加载所选模型窗口、输出预留、系统规则和实际可用的工具定义。
2. 按当前任务检索记忆和 Skill。显式选择及本轮已读取的规则优先；可选背景受独立预算限制，资料正文按需读取。历史 Skill 读取不自动成为新一轮的加载状态。
3. 构造至多一个位于对话之前的背景消息，包含历史摘要、必要知识、运行信息、时间和临时视觉证据。用户消息之后不追加任务状态或材料目录。
4. 保留对话顺序，工具调用与结果保持成对。当前用户消息按本次出现的位置保护，不做内容相似度去重。
5. 特别大的工具结果转为有限预览和原文引用。用户输入、工具调用参数和供应商推理签名不在实际请求中被局部改写。
6. 使用同一估算器计算系统提示、消息、工具 schema 和图片，再判断预算。

## 预算与压缩

窗口来自所选模型配置。输入预算扣除输出预留及安全余量；输出预留也用于模型请求的输出限制。触发阈值与目标按模型窗口计算，目标必须低于触发阈值。token 是估算值，不冒充供应商精确 tokenizer 的计数。

先移除可选检索背景，再压缩较早的完整交互。保留当前用户消息及最近的完整交互。目标是留出后续执行空间，不为达到比例而删除当前请求。

摘要模型接收旧对话、上一份历史摘要，以及用于判断相关性的当前请求。特别大的工具输入或结果在摘要输入中提供预览及原文引用；实际原文仍在 records 中。摘要必须通过 JSON 格式、长度、引用范围和 token 减少的校验。

每批验证成功后，摘要与剩余 active 一起保存。后续批次失败或用户中止不撤销已保存的有效批次。未通过校验的批次保留原文，不使用旧任务摘要兜底，不伪报摘要完成。输入仍超过预算时，明确报错，不发送超限请求。

## 中止、重试与恢复

中止是会话状态，不伪造 assistant 回复供下一轮模仿。已收到的文字、调用和结果按真实顺序写入历史。依据已检查点的消息数量追加增量，不按文本猜测重叠。

网络重试复用已准备的输入和已提交摘要，避免重跑已完成的工具。只有供应商明确报告上下文超限，才降低有效预算并重新进入同一个组装器。普通参数错误不触发另一套压缩算法。

摘要请求有独立的输出预算、较低推理强度和最长 60 秒的单次等待。取消信号终止等待；格式校验失败最多要求模型重写一次，失败后清楚报错。

## 日志与统计

AI 请求详情显示适配器报告的实际请求体，包括实际消息和工具定义；适配器未提供请求体时显示模型输入。请求体不混入 contextManifest、modelContextSegmentation、执行编号或检索诊断，不裁剪消息后冒充完整输入。普通请求、原生模式和摘要请求使用同一原则。

首次响应前的等待是独立进度事件。压缩开始、批次进度和完成也有明确事件，完成只在检查点保存成功后发布。

运行中使用本轮准备的请求统计。空闲、中止或新一轮尚未组装完成时，统计当前 active、保存的请求背景、系统提示和工具定义，不用上一轮旧计数替代当前上下文。

## 代码入口

- `runtime-context-assembler.ts`：背景选取、工具结果引用、预算、压缩计划与检查点。
- `runtime-semantic-summary.ts`：摘要输入及输出校验。
- `runtime-context-compression.ts`：工具调用链配对操作。
- `browser-chat-model-context.ts`：原始对话与持久化视图。
- `runtime-context-search.ts`：按关键词或引用回读原文。
- `browser-chat-executor.agent.ts`：模型执行边界、请求日志、重试与持久化回调。
