# Agent 上下文运行时：Hybrid v3

本文描述项目实际调用链采用的混合方案。参考输入为用户提供的 hybrid-agent-runtime 第三版工程；不启动其独立 CLI、数据库或第二套 Agent 循环。

完整调用链审查、问题清单及验证边界见 [2026-09-22 上下文系统审查](context-audit-2026-09-22.md)。

## 分工与请求顺序

- `runtime-context-assembler.ts` 是纯投影函数：稳定系统规则和工具 Schema → 有序活动窗口 → 必要时补回当前用户原文 → 当前任务状态及按需资料 → 历史对照图和当前截图。它不访问数据库、不检索、不调用模型、不写入记忆。
- `runtime-context-runtime.ts` 负责预算检查、调用 Compactor、保存替换窗口和刷新观察。原生模式继续由现有 AI SDK 7 循环驱动；Codex 模式仍为每次一个 action object。不会套入示例工程的另一层循环。
- `records/history` 保留原始证据；`active` 是独立检查点。恢复直接读取 active，不能用全量历史或事件重放重建窗口。
- 已加载的用户 Skill 正文、当前时间和截图属于请求尾部，不写回活动文字窗口。用户原始消息按顺序直接保留；不再提供 taskContext 或执行计划工具，也不注入这两类状态。

## 预算与滚动压缩

输入预算为 context window 减去协议安全预留，默认安全预留 4096。系统不设置模型输出预算，也不从输入容量扣除输出预留。压缩触发点默认是输入预算的 85%，目标是 25%，与设置界面及环境示例一致，均可通过现有环境配置调整。统计是启发式估算，包含系统、工具、消息、必需资料和图片。只有协议中的媒体片段排除媒体体，普通工具 JSON 的同名 type/data 字段仍计入文本；请求准入、压缩校验和发送日志使用同一份实际投影进行统计。

压缩从最旧的完整交互块开始，至少保留最近四块。assistant 工具调用和对应结果不可拆开，供应商在 assistant 消息内返回的工具结果也纳入配对。所有用户原始消息与完整 Skill 读取交互均跳过有损摘要；当前压缩批次在这些精确保留块之前或之后选取连续历史，不跨越它们。替换位置为原连续批次所在位置，精确原文、handoff 与近期交互的时间顺序不变。同一 Skill 的完全相同正文只需保留最近一次，不同版本仍不进入有损摘要。已加载用户 Skill 每次按当前授权及版本注入完整正文；引用附件仍按需读取。后续用户纠正优先，摘要不能覆盖原文或复活已取消的任务。已有 handoff 单独保留，避免在没有相邻新历史时二次有损压缩；原始证据仍在归档中。摘要输入单独限额，去除推理、媒体二进制和供应商私有元数据；当前请求的摘要相关性提示也采用同样的投影，主模型的当前原文不裁剪。摘要调用不设置最大输出 token，也不按固定输出长度拒绝摘要。模型输出普通文本，程序附加本批原文引用及顺序，标记为未验证的历史摘要；来源表示批次关系，不表示逐条事实已核实。输出必须正常结束、有正文并实际缩减完整请求，才递增 epoch 并提交。

达到触发线后，压缩循环持续到目标线，单次准备最多处理八个批次，不会仅因降到触发线以下就提前结束。单批摘要输入最多 64000 tokens，同时不超过当前输入容量的 60%；至少保留最近四个完整交互块。选择批次和发出调用共用摘要提示词构造器，选择时预留协议及错误修正提示空间，调用时检查实际完整输入。

摘要输入中的长正文、长文本片段和工具内容使用相同的预览、尾部、原文引用与指针投影；原文归档和当前固定请求不被截断。单个旧消息也可以压缩。只剩已有 handoff 与需保留的近期交互、下个完整块无法装入摘要输入、交互结果尚未完整或达到批次数限制时，记录 compactionStopReason，表示本次停止且可能未达目标，不伪造模型失败。主请求超出输入容量仍会停止。

每批摘要最多调用模型两次，不设置输出 token 上限，超时沿用运行时请求超时。空正文（包括空对象等纯标点输出）或实际缩减校验失败时，附带错误反馈修正一次；网络、限流、超时和服务端临时故障按统一退避策略重试一次。供应商返回 length/content-filter，或鉴权、配置等非临时请求错误时，不原样重复请求。同一轮对相同历史批次和固定用户请求缓存失败结果，后续准备步骤使用 skipped 事件说明沿用旧失败、本次未调用模型；新轮次或源批次变化可重新尝试。不要求模型输出 JSON 或逐条生成来源引用。

handoff、活动窗口、epoch 的存储记录与压缩审计在同一会话写事务内提交。摘要生成失败时，只有仍能装入输入预算才使用最近成功保存的窗口继续；已有成功批次保留，失败批次原文保留。超限则停止，不静默丢弃当前请求、固定约束或当前截图。摘要耗时后重新采集截图，再组装主模型请求。

主模型请求与摘要提示词投影都会折叠连续、目标理由与结果相同且未尝试任何浏览器动作的重复调用/回执，只保留这一串的最新完整交换。原始调用和结果仍在数据库及 `contextRead` 中，handoff 来源仍引用完整批次，主请求清单记录折叠数量；当前页面截图、用户原文和非重复调用不被该规则删除。运行时另附一次只读 DOM 与重复次数反馈，避免已经失败的调用模式在活跃上下文中反复示范。

日志将摘要请求、模型返回、校验重试和最终保存结果分开记录。模型返回事件展示真实 aiOutput、finishReason 和 usage，仅表示收到响应。仅在摘要通过校验并完成存储提交后发布压缩完成；真实生成或校验失败使用失败/部分完成事件，正常停止使用 limited 事件并说明未达目标。失败降级日志明确标记 fallback/terminal，不能把可继续的压缩失败当成整个对话失败，也不能把模型返回当成压缩成功。最终日志记录压缩前后 token 估算、处理数量和是否达到目标；刷新截图或动态资料可能使最终请求高于文字压缩目标。

contextRead 的内容来源在实时裁剪完整结果前保存为独立的 contentSource，图标与名称按内容生产工具展示。旧会话中的执行计划调用保留在证据库中，但不再进入新的模型请求。

供应商拒绝主请求为上下文超限时，重试阈值同时参考已拒绝请求的实际估算量，避免仅降低配置阈值却仍无法触发压缩。重试前若输入没有缩小则明确停止；成功推进到下个 SDK 请求后恢复普通阈值。摘要准备期间暂停主请求 watchdog，摘要调用保留自己的超时与用户取消信号。

## 历史、记忆和 Skill

已读取的文件原文由 `runtime-source-files.ts` 独立管理，不再作为普通浏览器日志反复摘要。文件 readContent 和 codeSandbox readFile 的分页结果绕过通用回执截断；原文先归档，活动工具回执仅保存读取身份和原文引用。每次准备请求，沿本分支活动窗口及宿主生成的 handoff 来源恢复已读范围，不扫描其他分支全部记录。同内容同读取条件去重。

文件原文使用最多约输入容量 45% 的独立资料区：已读内容可容纳时完整附加；过大时按当前请求、当前计划及最近模型动作选择精确文本片段，按行边界分块，保留原始字符偏移。每个已读范围始终有索引，包含原始读取请求、ref、pointer、总字符数和本次附加范围。遗漏细节通过 contextRead 精确回读，不能由摘要猜测；索引不意味着整个文件已读。文件资料是数据，不能扩大用户授权。正文以独立稳定消息注入，避免跟随时钟变化重复归档整份文件。压缩检查点同时保存新文件回执，保证后续 handoff 来源仍可解析。

请求 manifest 和执行日志记录 readRangeCount、fullyIncludedReadRanges、originalCharacters、includedCharacters，描述已返回文件范围的覆盖情况，而非伪称整份文件读取完成。

`contextRead` 是显式历史检索与原文读取入口。无 ref 时使用现有会话范围 BM25；有 ref 时按 JSON Pointer 和 UTF-16 字符偏移读取，使用返回的 nextOffset 翻页。完整工具结果在生成模型预览之前归档，预览提供原始 ref。指针按实际归档后的结构生成，不能沿用删除图片前的数组下标。分页响应不能再次截断后沿用旧 nextOffset。原生工具模式和 Codex action-object 模式共享同一输入 Schema 与读取实现；Codex 也将真实工具结果归档、投影到模型，调用 ID 与执行证据 ID 一致。

长期记忆在用户轮次边界最多召回一次，作为带版本和来源的历史资料写入活动窗口；后续查找由 memory 工具显式发起。它不是当前用户指令或当前页面事实。模型提议经过现有独立来源审查后，存入 candidate 表，宿主批准之前不进入可召回记忆。批准同时核对原记忆版本、权限与有效期，并原子提交变更和审核状态。历史版本、适用条件、来源与失效机制复用现有记忆存储。

会话侧提供“提炼本轮记忆候选”和批准/丢弃入口。提炼任务持久化到 agent_memory_job，包含租约、尝试次数、退避与终态；显式宿主 worker 执行。默认不自动提炼。AI_PERSONAL_MEMORY_AUTO_EXTRACT=true 仅启用完成轮次的自动入队，worker 仍由宿主触发，不在模型准备或工具执行路径中隐式提炼。

Skill 先提供目录，正文显式读取后持续保留。系统 Skill 保护其最近一次完整读取交互；用户 Skill 由资料解析器在每次请求注入当前完整正文，版本更新时替换，撤销权限或停用时停止注入。参考资源仍按需读取。普通结果可被引用预览代替，完整 Skill 正文及前置检查主动返回的当前版本 Skill 正文不得被通用预览裁掉。两种模型执行模式都按实际请求中在场的正文判断已加载状态；历史读取日志不能冒充正文。正文保留由运行时自动完成，不要求模型登记任务笔记。必需原文独自超出容量时明确停止，不偷偷摘要规则。Skill 正文不能扩大工具权限或覆盖用户要求。

## 浏览器观察与动作

设置 → 浏览器 → 浏览器观察中的 `BROWSER_CHAT_INTERACTION_MODE` 默认 `hybrid`，可选择纯 DOM（`dom`）、纯视觉（`visual`）、DOM + 视觉（`hybrid`）或官方 Playwright MCP（`mcp`）。复用环境配置保存链路，每轮执行开始时读取并保存为会话的 `browserInteractionMode` 快照；排队轮次开始时读取最新设置。原生模型、Codex 与分支 Agent 使用同一模式与动作分发器，切换不改变正在执行的轮次。输入框不提供模式开关。

MCP 模式使用 `@playwright/mcp` 的标准工具协议，经当前 BrowserSession 的 CDP/Playwright endpoint 连接同一浏览器。模型先以 `browser action=mcp, tool=list` 获取实际工具参数，再调用官方 `browser_*` 工具；`browser_run_code_unsafe` 不暴露。执行页面操作前根据 MCP 标签列表核对当前会话的唯一 URL；同 URL 标签不唯一时拒绝操作，避免误触其他会话。标签新增、选择和关闭仍通过会话原生 `navigate`/`tabs` 动作。MCP 服务进程按会话复用、会话关闭时释放。MCP 回执与截图仍走浏览器工具证据归档和当前截图投影，不把 MCP 成功回执当作业务成功。

DOM 模式通过当前 DOM 和 Playwright/locator 操作；支持图片的模型也接收最新视口截图作为结果证据。图片已经作为像素附加，无需另调读取图片工具；提示词要求模型在后续依赖操作前结合 DOM 检查可见状态。DOM 模式仍不开放视觉 act/images/observe 动作。纯视觉不开放 DOM、AX、locator 或脚本参数；混合模式开放两套动作。图片不受支持或当前截图不可用时，明确告知模型无法进行视觉检查，仍可使用 DOM。用户上传图片及文档预览独立保留。

`act` 每次执行一个完整手势，必须引用当前 observationId。支持 click、hover、move、drag、scroll、type 和 key；click 的 button/clickCount 表达右键、中键、双击和三击，drag 使用起点和终点，modifiers 支持按住 Control/Shift/Alt/Meta 的鼠标手势，key 支持同时按下的组合键。一个手势内完成按下、移动及释放，失败时也尝试释放输入状态。三种模式复用 BrowserSession 的连接、标签归属和生命周期；原始证据归档和中断续接机制保持一致。

截图独立保存为 PNG 文件，记录 CSS 尺寸、surfaceId、URL、内容哈希和采集时间。相同表面、URL 和像素复用 observationId；导航或表面变化重置默认选图。历史截图保留为执行证据；自动请求投影只附加一张最新浏览器截图，显式参考图和文档图独立保留。新的采集失败通知也会淘汰旧自动截图，不能沿用旧画面冒充当前结果。

视觉模式以及支持图片且启用自动截图的 DOM/混合模式，在模型请求前采集当前截图；压缩耗时后再次刷新。视觉动作执行前，包括批准等待之后，再次采集并比对；过期、变化和越界坐标不会执行。日志和 manifest 根据最终请求统计 browserScreenshotCount，表示已附加像素，不表示模型已正确检查。输入调用成功仅表示该调用执行，不代表业务任务完成。截图与点击之间的变化窗口无法完全消除。

纯视觉模式需要支持图片的模型，需要用户输入凭据或处理文件选择器时使用已有人工接管入口。DOM 与混合模式保留 SDK 的附件和凭据绑定协议。其他文件、终端、连接器仍保持各自工具边界，不得用于绕过选择的浏览器模式。

执行计划和长期记忆并排位于对话工具栏，点击后展开对应面板；计划继续展示完成数量并保留阶段审核、退回修正和继续执行入口。

## 持久化与恢复

agent_runtime_state 按 session/scope 保存 CAS revision、pending 和观察选择；agent_runtime_event 保存审计；agent_runtime_call 防止复用调用 ID。模型完整决策先存 planned，再进入等待批准/执行。多工具决策全部拒绝，不执行其中任何一个。原生 SDK 的执行钩子与 Codex 分发均接入相同日志机制。

工具完整结果先归档，再保存 pending 结果；完整交互写入 active 后清除 pending。执行中断缺少结果时记录 unknown，已保存的结果原样保留；尚未开始的 planned/awaiting-approval 决策记录 not-executed。续跑自动补齐结果并交回 Agent 重新观察、生成新决策，不重放原调用，不要求人工解锁。长期记忆面板只处理记忆提炼与审核，不包含执行恢复锁。动作输入成功后截图失败仅表示观察不可用，不改写输入执行结果。

协议安全预留只参与后端输入预算和压缩阈值计算。输入预算模块不读取模型额外请求参数，不产生任何模型输出上限；用户显式配置的请求参数仍由 provider 配置合并层透传。供应商协议和 SDK 自身的默认限制不属于应用输出预算。

SQLite 使用 WAL 和 synchronous=FULL；事务与 CAS 复用现有数据库抽象，也支持项目已有 PostgreSQL 路径。会话归属由原鉴权链验证，分支工具状态按 scope 隔离。

## 数据迁移与验证边界

`HybridRuntime1790000200000` 创建新状态、审计、调用、压缩、候选和任务表。原始归档不变；旧分段引用按顺序移入保存的 active，之后可合并为新 handoff。旧活动窗口中没有确定结果的工具交互进入 uncertain，旧调用 ID 保留用于防重放；旧请求展示缓存清理。之前尚未发布的 ContextRuntime 迁移仅创建任务状态和整理笔记，不再从全量历史重建窗口。

恢复校验覆盖主会话、分支、请求清单、handoff 和用户原文引用。缺失引用或非法消息明确报错，不通过过滤数组静默丢弃。SDK 新增响应边界先按原数组计算，再过滤临时视觉消息、修复工具协议；不能用过滤后的长度推算已消费的响应数量。工具配对核对调用 ID 和工具名，并排除重复结果。用户取消导致活动窗口未提交时，不确认清除 pending 执行记录。

迁移随应用正常数据库初始化执行。本次编辑不启动 dev/build，也不直接更改运行中数据库。不执行附件 MIGRATION.md 中针对独立示例数据库的导入命令。

验证应分别记录类型/静态检查、内联机制检查、真实浏览器输入检查和真实模型端到端检查，不能用前者代替后者。不创建新的测试文件。
