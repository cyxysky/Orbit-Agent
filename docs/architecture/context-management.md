# Codex App Server 会话运行时

浏览器聊天的主会话、子 Agent 和恢复入口均经过 `executeInteractiveBrowserTurn`，交由 Codex App Server 管理模型历史、工具迭代、自动上下文压缩和持久化 rollout。应用不再调用旧的 `prepareRuntimeContext` 或 AI SDK ToolLoopAgent 驱动这些会话。

## 请求路径

1. 宿主按用户和会话/分支隔离工作目录，启动 `codex app-server --listen stdio://`，通过 JSON-RPC 初始化。
2. 首次通过 `thread/start` 注册 Orbit namespace 的动态工具；数据库保存 thread ID 和工具定义摘要。后续使用 `thread/resume`。
3. 旧会话的活动历史仅在首次迁移时通过 `thread/inject_items` 导入。迁移载荷持久保存到确认成功；以后不再用应用的 active/history 组装模型请求。
4. `turn/start` 只传本轮输入、参考图片和当前运行资料。Codex 决定后续模型请求、工具调用与压缩时机。
5. `item/tool/call` 回到宿主校验参数、检查禁用工具、审批并执行。浏览器、文件、Skill、记忆和子 Agent 继续使用现有能力实现。Codex 内置 shell、browser、computer、web search 和子 Agent 功能关闭；外部模型不会收到 freeform apply_patch 等非宿主工具定义。
6. 通知转换为原有文字流、推理流、步骤、人工输入和产物界面。终答须经过 finalResponse 验证；审核沿用迁移前的输入来源：最后一次实际模型请求、同一步新增工具结果和最终回复。归档仅按需读取，不拼入全量历史。外部供应商沿用原有独立模型审核；原生 Codex 通过只读 fork 复制活动窗口进行审核，只允许宿主 contextRead。

## 模型与供应商

- `provider=codex` 使用 Codex 原生 OpenAI 登录。宿主登录文件按用户隔离复制，保留 Codex 后续刷新后的凭据。
- 其他供应商经过本机随机端口、随机 Bearer token 的 Responses 协议桥，继续调用现有 `getModel`。AI SDK 在这里仅完成一次模型生成，不维护主会话历史、不运行工具循环、不生成自定义上下文摘要。
- 协议桥翻译文字、命名空间工具、工具回执、图片和推理摘要；跨供应商加密 reasoning 不转发。连续的 assistant 输出项合并为一个聊天消息，同批工具调用一起放在该消息中，其后紧接完整的配对回执。工具返回的图片携带调用 ID 转成独立的用户图片内容，统一放在该批回执之后，避免打断工具调用链或被兼容供应商丢弃；同一次回执按文件路径去重截图。缺失、重复或顺序中断的工具回执明确报错，不伪造结果、不重放操作。无法转换的历史类型明确报错并保留线程。
- 非原生供应商使用 Codex 本地压缩路径。加密的远程 compaction 无法转换，因此原生会话经历此类压缩后切换供应商可能失败。
- 动态工具注册依赖 experimental API。项目不再内置 Codex CLI，运行时通过设置中的 `CODEX_PATH` 或系统 `PATH` 使用外部安装；此前协议验收基线为 0.144.6，外部程序须兼容所需协议。主对话、自动化和子 Agent 均依赖这个运行时，不限于 Codex 模型供应商。Codex 当前仅在创建线程时接收动态工具。现有工具的参数或描述升级保留原线程：外部模型由协议桥提供当前定义，原生模型收到更新定义的明确说明，宿主始终按当前参数校验。旧绑定缺少注册信息时只读取当前用户 rollout 的 session_meta 工具元数据，不读取或重组历史。工具名称集合变化时，在无活动轮次的前提下原子更新当前用户 rollout 首行的 Orbit 工具注册元数据，再恢复同一个线程；首行之后的全部历史字节原样保留，不重组或重放对话。

## 持久化与中断

`workspace_record(collection=execution, kind=state)` 的 `codex-app-server:<scope>` 记录保存线程所有权、版本、迁移状态和待确认回执。Codex rollout 保存在 `APP_DATA_DIR/codex/<user hash>`。数据库绑定与该目录必须一起保留；丢失 rollout 会报错，不会透明重建空会话。

原有执行 journal 仅负责操作安全和审计。调用 ID 在执行前持久登记，重复 ID 不重放。结果写入 journal 和待投递记录后才能回到 Codex；收到 dynamicToolCall 完成通知后才清除待投递记录。进程中断后，区分未执行、结果未知和已完成但未确认投递的操作，把恢复证据注入线程，要求检查当前状态，禁止透明重放。浏览器视觉引用亦持久保存，恢复后可继续按已有图片 ID 取证。

取消通过 `turn/interrupt` 传入 Codex，同时把 AbortSignal 传给宿主工具。关闭连接前等待正在处理的工具登记结果。人工输入工具或被接受的 finalResponse 返回后中断本轮，保留线程供后续恢复。终答审查服务不可用时本轮明确失败，不接受未经核对的终答。

应用的 `modelContext.records`、消息历史和 rawResult 是界面/审计归档，并提供 contextRead 检索；不是后续模型请求的权威活动窗口。旧摘要及历史解析模块保留用于读取历史数据，已退出主执行路径。

上下文检查点等待本次快照对应的数据库事务提交；并发的进度保存不替换该等待对象。真实保存失败保留底层 cause，界面刷新通知失败不会中断模型会话。持久化刷新通知在事务提交后发送；聊天刷新载荷超过 6 MiB 时仅发送失效通知。界面按会话合并通知并间隔至少一秒后台读取对应记录，不进入首次加载状态、不重置历史列表或阅读位置；重新连接时仍同步会话列表。完整记录不截断、不丢弃。

## 输出与追踪

App Server item ID 对应稳定的界面输出记录。按原生 item 开始顺序保存文字、思考和动态工具，工具开始、结果和完成快照更新同一条记录；不通过累计工具列表推断位置。旧迁移回合缺少工具位置时，在读取会话时用已保存的转录与调用 ID 恢复展示顺序，不重放操作、不改动 Codex 上下文。

宿主工具持续写入 `ai:tool` 追踪，保存调用 ID、参数、原始结果、耗时、进度和执行异常。模型桥记录实际请求、响应、用量、输出性能和供应商异常；原生连接记录线程、回合和 item 关联信息。Error 的 message、stack、cause 与 RPC 错误详情在序列化前展开。界面保留终止错误及压缩生命周期，失败工具优先显示业务错误原因。旧回合未写入的异常栈无法仅凭回执恢复。

原生文字终答通过同一个宿主 finalResponse 完成审核入口处理。审核拒绝时把反馈交还同一 Codex 线程继续执行；审核不可用时明确失败。正常回合不会仅因模型没有显式调用 finalResponse 而被判为运行时失败。

外部模型的终答审核保留原有模型容量检查、按证据引用读取和有限恢复，采用与主请求一致的流式传输，逐块检查供应商异常并约束首包等待、总时长和取消。审核请求与完整回复单独记录，包含流式标记和耗时；网络断开分类为 network，工具异常保留 cause、错误码及审核尝试次数。不把归档重新展开成 App Server 的 turn/start 文本，避免触发该接口的 1048576 字符限制。面向用户的终止失败提示为“会话执行失败”。

## 独立文本编辑

textEditor 与文本编辑界面共享当前用户的 text-documents/<user>/documents.db。每份文档独立保存 title、format 和完整 content，format 为 text、markdown 或 html，不包含章节、大纲、版本、审核或确认流程。create/list/read/write/edit/append/delete/export 均直接执行，包括严格模式。读写按 documentId 操作，事务失败不提交部分修改；可使用 expectedContent 防止覆盖读取后发生的其他修改。

read 不指定范围时返回完整源码；offset/limit 支持分段读取，contentRange 返回范围、总字符数与 nextOffset，按 UTF-16 计数且不拆开 Unicode 字符。edit 按精确且唯一的 oldText/newText 批量替换；任一缺失或歧义匹配都会回滚整次调用。宿主的 tool_output_token_limit 为 32768，原始回执保留在日志和 rollout 中。

编辑器支持新建、导入、自动保存与导出 .txt/.md/.html。Markdown 使用格式化预览，HTML 使用无脚本权限的隔离 iframe 与 CSP 渲染。选区工具栏提供复制和 AI 改写，AI 卡片可拖动或用方向键移动；整篇改写入口也支持空白文档生成。修改建议应用到当前源码，保留选区外的后来修改；整篇修改要求原文未改变。旧 novels.db 只读导入为普通 Markdown 正文和创作笔记，使用持久导入标记防止删除后的文档再次出现，旧数据库保持原样。

## 配置和用量

- 自举权限由启动环境变量 `ORBIT_SELF_BOOTSTRAP_ENABLED` 控制，默认 `false`，首次权限检查后固定。运行配置和会话参数无法提升此权限。关闭时，主对话和子 Agent 的目录及调用分发共同排除终端、电脑、本地代码沙箱和本机 Runner，终端 HTTP 接口也直接拒绝请求。文件工作区使用宿主传入的独立执行权限，新建 Word/PPT/PDF 使用静态 HTML，旧 Python/JavaScript 草稿的验证与渲染同样受限。普通文本、读取、下载和独立远程沙箱继续可用。开启时沿用已有工具开关和审批，模型提示包含项目目录以支持用户要求的源码修改。
- 身份管理、数据库连接和服务部署以外的配置统一保存在数据库，通过 `/api/settings/runtime` 按键增量保存。模型与 MCP 沿用各自的配置接口。API 与执行进程每秒刷新独立快照，保存进程在数据库提交后立即发布。独立设置键与模型列并发保存不会互相覆盖。SDK 能力通过 Manifest 配置存储取得自身声明的字段。
- 新请求使用新配置，延迟加载的模型客户端绑定其创建时的快照，避免模型与凭据混用。Codex 每轮重新创建 App Server 连接，并在同一线程的 `thread/resume` 中传入当前配置。浏览器的实例级配置在相关执行空闲后自动释放旧实例并重新接管。托管沙箱在执行空闲后更新，新的执行请求等待配置切换。脱敏工作进程在现有请求完成后按模型配置指纹自动替换。实时预览读取宿主配置，采样和编码参数变更时自动重建采集流。
- 首次升级只导入旧 `.env` 中尚未保存的业务配置，保留已有数据库值并记录迁移标记。原 `runtime_env_json` 列继续存放已有数据，应用接口与类型统一为 Runtime Settings。
- 独立 Runner 的连接地址与凭据属于服务部署，使用 `ORBIT_CODE_SANDBOX_SERVICE_URL` 和 `CODE_SANDBOX_RUNNER_TOKEN` 提供连接默认值，数据库中保存的工具配置优先。桌面端通过服务路径提供已安装浏览器与用户资料目录。品牌名称沿用设置页的浏览器存储及即时同步。
- 模型最大上下文优先；外部模型未配置时使用 AI_CONTEXT_WINDOW_TOKENS，默认 256000。
- AI_CONTEXT_COMPRESSION_TRIGGER_RATIO 映射到 Codex 的 model_auto_compact_token_limit；删除旧的压缩后目标比例设置。摘要策略由 Codex 决定。
- 外部模型的 Context usage 从协议桥收到的实际模型请求计算，包含消息与系统文字、实际发送的工具定义和图片，不将图片 base64 当成文字计费。收到供应商用量后，总量校准为实际 input tokens，文字/工具/图片分项按估算占比分配并明确标注；后续同一模型的请求预测参考最近一次实际输入与原始估算的比例。统计用于展示，不参与 Codex 的上下文组装或压缩决策。
- 原生连接使用 `thread/tokenUsage/updated` 的 last.inputTokens 和 modelContextWindow，不把输出 token 算进输入上下文。协议未提供的分项显示为“未知”。统计随线程绑定保存，恢复会话时沿用已有用量，首次尚未收到请求用量时总量为 0。
- 工具调用前后关联相邻真实请求的 ID 和输入用量，同一请求的工具共享该次增量。协议桥的模型请求耗时保留到工具追踪。终答被接受后没有后续请求时不编造调用后用量。旧日志读取时从已保存的实际请求和匹配的供应商响应恢复统计，不重新执行工具或模型请求。
- 外部模型的请求超时与首包等待由模型桥约束；重试次数交给 Codex 供应商配置。宿主不重试 turn/start 或已执行的工具操作。

## 验证范围

使用已安装的真实 Codex 二进制和本地模拟模型接口验证动态工具循环、现有 Skill/finalResponse 宿主入口、终答审查、同线程进程重启恢复、历史迁移、分支隔离、取消后的不确定回执恢复和 Codex 本地压缩。上下文统计验证包含图片分项、供应商输入用量校准、相邻请求的工具统计、API 耗时和线程恢复；旧会话日志通过只读方式核对。模拟接口验证协议与宿主接线，不代表真实供应商端到端行为已验证。
