# 用户隔离与 Cookie 身份绑定

核查范围：API 路由、挂载初始化、上传和生成文件、文本工作区、自动化记录、实时刷新与响应操作。ID 定位资源后，服务端必须再校验当前用户归属；前端隐藏入口不能代替归属校验。

| 内容 | 隔离边界 |
| --- | --- |
| 对话、历史消息、日志、上下文、终端和预览 | 当前身份的 userId 与会话 owner 匹配；子记录归属于 sessionId |
| 上传 | `uploads/<userId>/...`，下载和 HEAD 均校验用户 |
| 对话生成文件 | 顶层执行 ID 对应的会话 owner |
| 自动化任务、计划、执行记录和生成文件 | 存储层以 user_id 查询；执行文件也允许按自动化运行 ID 确认归属 |
| 用户持久文件与通信草稿 | `users/<userId>/...`；草稿写入此命名空间 |
| 文本编辑文档、修改建议 | 按 userId 分目录的文档库，读取和应用建议都验证 documentId |
| 图表、地图及其他响应操作 | 先验证会话或自动化运行归属，再执行内容操作 |
| 实时刷新与 WebSocket | 票据包含 userId；消息按用户分发，启用 Cookie 校验后握手同时核对 Cookie 与票据归属 |
| 记忆、Skill、登录账号 | 私有记录按 userId 读取；明确标记 shared 的内容按共享策略开放 |
| 模型、工具、MCP、安全配置与 AI 运营 | 属于部署或管理员管理范围；不承诺这些全局配置是用户私有数据 |

本轮修复了未知文件命名空间默认放行默认用户的分支，以及缺失会话 owner 时自动归入默认用户的判断。现在没有明确归属的会话和文件，对默认用户也返回不可访问。

## Cookie 字段与环境变量

新增 `application_user` 表，以 `id` 为用户主键。`cookie` 保存 AES-GCM 密文；`cookie_domain` 保存域名，`cookie_fingerprint` 保存 HMAC 指纹，接口不会返回 Cookie 或指纹。多域浏览器 Cookie 注入仍保存在 `browser_domain_cookie`，与每用户一组活动身份绑定分开管理。

```dotenv
ORBIT_USER_COOKIE_CHECK_ENABLED=false
# 建议填写实际登录 Cookie 的名称，多个名称以逗号分隔。
ORBIT_USER_COOKIE_NAMES=session
```

同样接受对应的 `WEBPILOT_` 前缀；同时配置时以 `ORBIT_` 为准。这两个变量属于部署配置，修改后随正常服务重启生效，不在设置页即时开启。私有 `.env` 已加入默认关闭的配置，示例见 `.env.example`。

未配置 Cookie 名称时，比较所有非 Orbit Cookie；配置名称后，必须存在全部指定字段。比较前按名称排序，因此请求头顺序变化不会导致失效。Orbit 身份 Cookie、界面语言和侧边栏偏好不参与比较，也不会被注入业务站点。

## 启用顺序

1. 保持校验关闭，通过可信挂载流程取得当前用户的 Orbit 身份。
2. 使用已有 `POST /api/browser-cookies/domp`，请求 JSON 为 `{ "userId": "42", "domain": "example.com" }`，登录 Cookie 由请求头传入。
3. 服务端检查签名挂载身份、提交 ID 与当前 ID，原子保存身份绑定和浏览器 Cookie。相同域名的同一指纹不能绑定不同用户。
4. 完成所需用户绑定后开启 `ORBIT_USER_COOKIE_CHECK_ENABLED=true`，按部署流程重启服务。

开启后，未绑定、缺少登录 Cookie、Cookie 与 ID 不一致均拒绝访问。挂载初始化在读取历史和签发身份票据前校验所提交 ID；普通 API 在读取文件、修改数据或转发给执行进程前校验；WebSocket 在升级前校验身份及票据归属。

Cookie 刷新后，仅持有现有有效签名挂载身份的用户可通过同一保存接口更新自己的绑定。更新撤销该用户尚未使用的 WebSocket 票据；后续旧 Cookie 请求被拒绝。宿主系统必须先确认业务登录会话与 userId 的归属，再提供挂载身份；此机制校验已经建立的绑定。跨站部署须确保请求实际携带被绑定的业务 Cookie，通常通过业务站点的同源反向代理完成。

已有管理员内部调度在私有通道中使用可信服务身份，不依赖浏览器登录 Cookie。外部提交的身份来源和用户请求头会被公开服务清除，再由服务端重新签注。

验证：使用独立 SQLite、临时文件和真实 HTTP 路由，覆盖双用户文件、对话、文档访问，Cookie 错配、未绑定、重复绑定、轮换、伪造头及票据撤销。未操作真实用户数据。明确共享内容和管理员全局视图保留现有策略。
