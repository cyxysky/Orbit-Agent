# 浏览器输入、标签页与浮层检查

日期：2026-09-22。修改位于 `packages/capability-sdk/src/browser`，没有针对 Angular、特定站点或组件库添加分支。

## 输入

Playwright 的 `keyboard.type` 原本就逐字符输入，可以显式使用 `{ delay: 80 }`。原有 BrowserSession 键盘路径却优先在页面内一次写入 value，然后人工派发键盘、input、change 事件；视觉 type 也使用整段 insertText。现移除该 DOM 写入捷径，统一这些 type 路径为原生逐字符输入。BrowserSession 的字符间隔默认 50 ms，可用已有 `BROWSER_KEYBOARD_TYPE_DELAY_MS` 调整；`tab.cua.type` 支持 delay，默认 50 ms。直接调用原生 `page.keyboard.type` 仍遵守显式 options。

逐字符输入不保证框架已提交值。中文等非美式键盘字符可能只有 input 事件，并不模拟完整输入法组合过程；blur、校验和 debounce 仍由应用决定。模型指导要求验证搜索结果、校验或保存结果，不人工调用框架事件，不盲目按 Enter。

## 标签页

发现三处状态不一致：内核 tabs.new/use 原先只改变 page 绑定，没有同步前台；弹出新页后宿主仍可用返回的旧绑定覆盖已选择的新页；异步预览可见性查询可能晚于显式切换返回，并覆盖新状态。

现显式选择调用 bringToFront；宿主按是否实际执行 tab.use 区分选择意图，普通读取和弹出页点击不再用旧绑定覆盖当前页。预览同步及可见性通知核验当前选中页与选择序号；显式激活在异步操作前登记序号，过期激活放弃后续切换。预览截图路径本身不新增激活操作。

这些是代码中可复现的路径，不能据此确定用户某次现场跳页一定由预览触发。原生有窗口浏览器及完整实时预览尚未端到端复验。

## 浮层

- 原先 opened 要求操作前完全没有浮层，closed 要求操作后完全没有浮层；弹窗内的下拉菜单因此被误判。现依据具体 id 的出现、消失判断，支持显式 surfaceId，保留父弹窗不算关闭失败。
- 每个代码调用中的第一次非坐标操作可能缺少 before 状态。现操作前建立基线，后续沿用操作后的观察，支持同一调用内验证。
- 定位在前景但 z-index 较低的语义菜单/listbox/tree 原先可能不是活动浮层。现结合语义、定位和命中状态识别，不依赖高 z-index。
- 内嵌普通控件原先可能让父弹窗不再属于叶子节点，导致整个活动浮层消失。现只在真正的浮层集合里选叶子节点。
- 模型指导记录下拉浮层 id、入口及成功关闭方式，已知选择、关闭和验证合并执行；不重复无效 Escape，不在关闭后再次点击入口重新打开，不移除遮罩 DOM。

## 补充：输入事件与交付判定

`keyboard.type` 对中文逐字产生可信 input，但不产生美式键盘的 keydown/keyup，增加 delay 不会改变这一点。普通文本框失焦后才产生原生 change；框架的 ngModelChange 或自定义组件输出是另一层行为，不能混称。隔离 Chromium 实测两个中文字符产生两个 input、零 keyup、零 change；调用原生 blur 后产生一个可信 change。

直接 keyboard.type/insertText 现检查当前可编辑焦点，并在真实控件上观察原生事件和输入值是否变化。没有可编辑焦点、只读控件或输入被阻止时明确失败；不补发合成事件，不修改框架状态，也不自动触发可能关闭候选列表或提交表单的失焦/Enter。观测只输出事件计数及长度，不记录输入内容。iframe 与 Shadow DOM 中的焦点输入检查通过。

这证明通用输入机制和失败判定，不证明现场账号选择组件已正确更新其模型。现场截图无法确定该组件监听 input、keyup、composition 或选择事件，尚未在业务页面重现并验证其具体提交机制。
