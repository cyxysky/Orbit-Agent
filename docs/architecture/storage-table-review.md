# 数据表精简审查

本次按当前生产代码的读写调用链审查，没有执行删表或修改已有用户数据。SQL 初始化脚本当前仍为 34 张表；功能分组见 [PostgreSQL 初始化说明](../deployment/postgresql-initialization.md)。

| 表 | 当前用途与读取情况 | 判断 |
| --- | --- | --- |
| `agent_runtime_event` | `RuntimeExecutionJournal.save` 在每次状态变化时写入事件及整份 pending 交换；恢复读取的是 `agent_runtime_state`，当前没有事件查询 API 或其他生产读取方 | 优先删除候选。可移除事件写入及此历史表；要同时调整迁移和运行归属外键，不影响当前状态的原子保存和 revision 校验 |
| `agent_runtime_compaction` | 每个压缩 epoch 写入 active 引用和摘要快照；当前恢复读取会话头及 `browser_chat_context_record`，没有压缩历史读取方 | 优先删除候选。当前快照与不可变上下文记录仍须保留 |
| `user_onboarding_state` | 每用户一条引导进度，与 `application_user` 同为用户级一对一元数据 | 可合并到用户表，减少一张表；需要统一用户行的创建与引导状态更新入口 |
| `browser_chat_file_message` | 消息中的文件信息投影，由触发器同步；文件列表明确读取此表 | 保留。它避免为文件列表读取完整消息正文，删除前需要替代查询及大对话性能证据 |
| `agent_runtime_owner` | 为对话和自动化执行提供共同的运行归属，运行状态外键引用它 | 保留。直接重新关联对话表会使自动化执行遇到外键约束错误 |
| `agent_runtime_call` | 工具调用 ID 的唯一性记录，在计划阶段写入并由主键约束拒绝重复调用 ID | 保留。它的约束用途不依赖 SELECT 查询，不能按“没有查询”判定无用 |
| `personal_memory_receipt` | 处理回执被读取以判断某来源是否已经合并到记忆 | 保留。不能与仅用于后台执行的记忆任务直接混用 |
| `browser_domain_cookie` 与 `application_user` | 前者是每用户多站点的浏览器凭据，后者是每用户一组活动身份绑定 | 保留分离，两者的唯一键、用途和更新范围不同 |

明确的第一批精简空间是两张仅写入的运行历史表；用户引导进度合并后还能减少一张。这里给出代码调用链结论，没有将这些候选误写成已完成的数据库迁移。

其他业务表的合并应以相同实体、相同生命周期和相同权限边界为依据。消息、日志、自动化计划、凭据、Skill 等仍需要各自的分页、索引和删除语义；表数量本身不能替代这些判断。
