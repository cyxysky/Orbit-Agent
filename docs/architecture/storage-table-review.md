# 数据表与存储精简

当前服务端共 **6 张业务表 + 1 张 TypeORM 迁移表，共 7 张物理表**。桌面端另维护一张 electron_state，合计 8 张。迁移按顺序执行，业务表从 33 → 22 → 18 → 6；服务端初始化不创建 Electron 表，也不删除未知第三方表。

| 物理表 | 内容 | 约束与行为 |
| --- | --- | --- |
| runtime_meta | 应用配置、知识版本、管理员会话 | 配置加锁；版本由数据库触发器原子递增；管理员令牌仅存哈希 |
| workspace_entity | 对话头、运营归档、自动化定义/计划/运行、通信会话、执行归属 | 类型与 ID 复合主键；计划和运行隶属定义；计划删除保留运行；定义删除级联计划与运行 |
| workspace_record | 对话消息/步骤/日志/上下文/清单/文件投影、执行状态/调用/变量、记忆流程、通信入站消息 | 集合/分区/类型/作用域/ID 复合主键；数据库检查类型和归属；会话级联、revision、TTL、租约、重试及调用去重 |
| knowledge_record | Skill 与记忆条目 | 类型与 ID 复合主键；用户和共享范围过滤；记忆自然键唯一；独立知识版本 |
| user_record | 用户档案、账号凭据、站点 Cookie | 类型/用户/ID 复合主键；账号 ID 全局唯一；账号自然键、Cookie 绑定唯一；密文按用途隔离 |
| request_record | WebSocket 票据、API 幂等记录 | 用户/类型/作用域隔离；票据哈希唯一和原子一次性消费；请求指纹与响应重放 |

另有 typeorm_migration 保存已执行迁移，当前 12 条。上述共享表使用明确的类型投影和定向 SQL，未引入兼容视图、运行时 SQL 改写器或按业务例外分支。常用查询保留类型、用户、时间、租约、调度索引。

## 用户、账号和 Cookie

原 application_user、login_account、browser_domain_cookie 合并为 user_record 的 profile、account、cookie 三类记录。

- profile：每个用户一条，记录 Cookie 身份绑定及引导进度；更新引导进度不会覆盖 Cookie 绑定，重新绑定也不会覆盖引导进度。
- account：账号 ID 全局唯一；同一用户的域名与用户名组合唯一。共享只影响账号读取，修改和删除仍要求所有者身份。
- cookie：同一用户和域名一条，替换时只更新该域名的密文。不同用户可以保存同域名各自的 Cookie。
- 账号密码、站点 Cookie、身份绑定 Cookie 继续使用各自的加密列和附加认证数据，不复用密文。数据库检查阻止跨类型混填密文；迁移原样复制密文，不需要解密、重新绑定或重置凭据。
- 身份绑定的域名与指纹仍有唯一约束，禁止同一登录 Cookie 同时绑定多个用户。Cookie 校验开关、可信挂载绑定和管理员登录规则保持有效。

## 数据完整性与空间

对话、归档、自动化和通信可以使用相同 ID 而不互相覆盖。文件投影只隶属同一对话内的消息；删除消息会级联删除投影。运行状态按执行归属和作用域隔离。记忆候选和任务随对话删除，处理回执继续去重；通信入站维持原有软引用和全局消息 ID 去重规则。

记忆候选以 SHA-256 内容指纹替代完整旧快照；已审核候选与终结任务清理输入。大日志、上下文和请求清单继续使用 Gzip 无损存储，见[存储压缩说明](storage-compaction.md)。减少物理表主要简化结构，并不意味着 SQLite 文件立即同比缩小。

## 升级与验证

停止旧应用并备份数据库后，再启动新代码。迁移在事务中复制数据和约束，先删除旧子表，再删除旧父表；运行代码只读写新结构。迁移只向前，需要回退时恢复备份。旧表释放的 SQLite 空间仍需既有整理维护回收。

当前验证使用隔离 SQLite 与 PGlite PostgreSQL 内核，执行空库初始化、18 类旧存储逐列比对、密文和压缩正文保留、外键与级联、分页与索引、账号凭据、Cookie 绑定、自动化租约/去重、记忆审核/重试、运行恢复和管理员鉴权。未启动项目 dev/build，未新增测试文件，未向真实模型发请求；业务数据库未迁移，未连接部署中的 PostgreSQL。
