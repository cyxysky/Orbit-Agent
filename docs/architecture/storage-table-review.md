# 数据表合并

当前为 **22 张业务表**，另有 1 张 TypeORM 迁移记录表。原有 33 张业务表减少了 11 张；运行代码只读写合并后的结构。

| 原来的存储 | 现在的存储 | 保留的行为 |
| --- | --- | --- |
| 消息、步骤、日志、上下文记录、请求清单、文件消息投影（6 表） | `conversation_record`，用 `kind` 区分 | 按会话与类型分页；文件投影不包含完整正文；删除消息时级联删除其文件投影 |
| 运行状态、运行事件、调用去重、压缩快照、浏览器变量（5 表） | `execution_record`，用 `scope_id + kind + id` 区分 | revision 并发校验、调用 ID 唯一性、变量 TTL、执行归属及级联清理 |
| 应用配置 | `runtime_meta` 的 `app:runtime`、`app:model` | 配置分开加锁和保存，避免互相覆盖 |
| 用户引导进度 | `application_user.onboarding_json` | 与 Cookie 绑定独立更新，不覆盖身份凭据 |

管理员会话也使用 `runtime_meta`，没有为登录额外增加表。数据库只存会话令牌的哈希和会话元数据。

合并后的主键包含原来的归属与类型：不同会话可以使用相同消息 ID，不同执行范围可以使用相同工具调用 ID。文件列表继续读取轻量文件投影；索引支持按会话、类型、时间及步骤序号查询，不需要加载整个对话。

自动化的任务定义、计划和执行记录保留为三个实体；Skill、记忆、记忆回执与后台队列也保留各自约束。站点凭据是每用户多站点记录，身份 Cookie 绑定是每用户一份，两者没有强行合并。表数量减少不等于数据库文件会立即按比例缩小；数据量、索引和 SQLite 空闲页仍影响文件大小。

迁移在事务中复制已有数据并删除被替代的物理表，没有旧表视图或运行时兼容分支。旧迁移文件仅用于既有数据库的版本记录和一次性升级。升级时应先停止旧应用进程并备份数据库；迁移不可反向拆表，需要回退时恢复备份。

[PostgreSQL 初始化说明](../deployment/postgresql-initialization.md)提供空库初始化方法。定向验证覆盖了独立旧 SQLite 库升级、空 SQLite 库、生产存储函数，以及 PGlite PostgreSQL 内核中的初始化和文件投影；没有修改业务数据库。
