# 工作区切换与内存观测

## 点击后先切换工作区

四个工作区现在通过共用导航状态先显示目标菜单、标题和骨架屏，再由 React transition 执行 Next 路由切换。原页面只在请求期间隐藏，路由提交后正常卸载；没有将四个完整页面常驻内存。连续点击时以最后一次目标为准，返回当前工作区或浏览器历史导航可以退出等待状态。

对话、自动化、设置新增 `loading.tsx`，AI 运营沿用同一加载外壳；聊天大组件的动态导入也复用外壳，避免路由加载结束后再次丢失侧栏。链接改用自动预取，允许 Next 先预取加载边界。参见 [Next.js loading 约定](https://nextjs.org/docs/app/api-reference/file-conventions/loading)。

加载外壳沿用当前主题、侧栏折叠状态和服务端给出的菜单访问权限。角色和设置路由校验仍由服务端完成，骨架屏没有提前读取目标页面的私有数据。

2026-11-06 最终本地镜像 `38669b86be09` 的生产页面通过 Cap SDK 浏览器验证：人为延迟 RSC 请求 1.5 秒后，四个入口从页面收到点击到首帧展示目标标题、选中菜单和骨架屏约 47–114ms。这个数字是导航反馈时间，不是目标数据完全加载时间，也不含 SDK 点击前的动作预检。返回源工作区时草稿保留，连续切换以最后一个目标为准；1440px 浅色、390px 深色加载布局无横向溢出，窄屏改用顶部导航和单列内容。

本轮完成生产类型检查及容器内前后端编译，未运行宿主机 dev/build，未新增测试文件。验证使用新实例，没有执行真实模型任务。

## 既有优化与历史采样

此前已拆分了设置入口与可选设置区域、自动化运行结果的富文本渲染依赖。未打开的知识库、Skill、MCP、安全运行面板及自动化结果不会仅因进入页面而加载全部实现。工具目录和外观偏好轮询结果未变化时，不再通知订阅组件或反复写入本地偏好。

API 配置刷新合并并发读取，避免多个页面初始化请求各自排队刷新同一配置。配置保存后仍会读取新快照。

四个主工作区使用内部滚动容器，公共导航禁用不必要的页面级自动滚动，减少切换提交阶段的布局计算。侧栏折叠偏好在值未变化时不再同步重写 localStorage 和 Cookie。AI 运营的图表、异常任务与用量表格通过通用 `DeferredContent` 接近视口时挂载，首次显示后保留组件状态，避免刚进入页面就集中挂载所有 React Aria 表格。切换统计时间范围和手动刷新也使用内容区骨架屏。

生产页面采样发现固定尺寸的 Dock 在挂载时仍读取图标位置，单次强制布局约 10–18ms。通用 Dock 现在在禁用放大或无有效鼠标坐标时跳过位置测量；启用放大时仍保留鼠标和键盘聚焦行为。

最终 Docker 生产页面的已加载路由采样中，点击到提交后两次 `requestAnimationFrame` 约 41–65ms；修复后未再记录到 Dock 的慢位置测量。实例使用新数据库，AI 运营在独立浏览器中注入 42 条异常、4 个模型、2 个用户的统计样本，仅用于验证前端挂载成本。首次自动化切换仍约 464ms，包含尚未完成的路由资源加载；不能据此声称冷启动或所有场景已无卡顿。SDK 点击前的动作预检单独计时，没有算成页面点击后的阻塞。

AI 运营使用有界分页读取，只投影需要的会话元数据，在 SQLite 内计数修复标记。同步 SQLite 只读查询进入独立工作线程，保持只读权限；线程空闲 10 秒回收，数据库关闭或切换时同时释放。相同统计请求共享一次读取，最后一个调用方离开后取消剩余工作，单个调用方退出不会中止其他调用方。

本地采样中，原统计读取约 6.49 秒、主线程最大间隔约 2.32 秒；修改后约 1.98 秒、最大间隔约 86ms，API 堆增量由约 54MiB 降至约 13MiB。文件系统缓存和并行负载会影响总耗时，数据用于定位阻塞来源，不代表所有部署的固定性能。独立验证中取消读取约 26ms，并确认取消后可恢复查询以及工作线程拒绝写入。

浏览器实测确认开发服务首次编译路由也会影响切换，首次自动化路由响应约 7.9 秒，首次 AI 运营约 3.3 秒；已加载路由切换约 0.25–0.35 秒。未通过重启清缓存制造对照，也未将后续热缓存访问当作冷启动修复证据。未运行 dev/build，后端修改在正常部署重启后生效。

后端状态增加 API 与执行进程的 RSS、JS 堆已用量、已分配量、堆上限和外部内存，以及系统总内存和可用内存。API 每 5 秒通过私有 IPC 采样，页面仍按 10 秒周期读取；RSS 合计指这两个 Node 进程，JS 堆是各自主线程的 V8 堆。RSS、JS 堆和外部内存不能相加作为另一份总量。

内存采样器已通过独立父子进程的真实 IPC 验证。页面使用这份独立进程快照检查了浅色、深色和窄屏展示；当前运行中的旧后端未重启，因此不将界面校验用的数值当作部署实例的占用量。

AI 运营与后端状态共用 `DataTable`。表格和排序使用 HeroUI Table；分页使用 Pagination、Select 和 NumberField；筛选使用 Popover、Form、TextField 和 InputGroup，已应用的条件使用 Chip 和 CloseButton。分页和筛选的交互控件不再手写原生表单控件，其自定义 CSS 仅保留布局和宽度。状态使用 HeroUI Chip，操作使用 HeroUI Button，任务标题、模型与用量说明复用统一的单元格组件。

使用 Cap SDK 验收时复现了页面刷新期间的输入预检错误：序列化到浏览器的回调引用了仅存在于 Node 的 `CodedError`。现在回调只返回状态，由 Node 构造明确的预检错误；iframe 归属检查采用相同边界。独立真实浏览器验证确认运行时缺失时按钮点击数保持 0，恢复后点击数为 1。

Linux 容器验证还发现浏览器代码内核在加载 Patchright 时，被 Node 权限模型拦截了 WSL/容器环境检测。内核现在仅允许读取检测所需的六个系统元数据路径，不开放整个 `/proc`、`/run` 或宿主文件系统，也不增加这些路径的写权限。
